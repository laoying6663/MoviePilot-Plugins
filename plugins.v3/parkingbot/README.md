# 不可躺自动抢车位（ParkingBot）

自动把车停到他人私家车位上赚金币，停够设定时长后自动挪车结算收益。
登录身份复用 MoviePilot「站点管理」里 `tangpt.top` 站点已保存的 Cookie，不重复维护第二份登录态。

## 前置条件

1. 在 MoviePilot「站点管理」中添加并成功登录 `tangpt.top`（能通过连通性测试）。
   插件会用这份主站 Cookie 自动换取游戏会话，不需要你手填任何 Cookie。
2. 账号在游戏站点 `https://qcw.tangpt.top/` 至少拥有 1 辆车辆。

## 登录是怎么处理的

游戏站 `qcw.tangpt.top` 是独立子域，**主站登录 Cookie 不能直接用于游戏接口**。
插件的处理方式是：

1. 读取「站点管理」中 `tangpt.top` 站点已保存的 Cookie；
2. 请求主站 `https://www.tangpt.top/parking.php`（游戏登录页「从主站登录」按钮指向的地址），
   逐跳跟随跳转链，收集每一跳下发的 `Set-Cookie`；
3. 拿到会话 Cookie 后**回游戏验证一次**，确实能过 `/api/state.php` 鉴权才缓存 1 小时；
   验证不通过则不缓存，并把每一跳的状态码、跳转目标、新增 Cookie 打到日志里。

> 注意：不要用 `tp-open-connect/sso/generate`。那是游戏**退出登录**时跳转的解绑入口，
> 用它请求能正常返回，但换不到游戏会话，游戏只会一直判「未登录」。

全程不涉及账号密码、不涉及验证码，因此没有连续登录失败封 IP 的风险。
主站 Cookie 掉线时，由 MoviePilot 站点管理侧负责更新，插件下一轮会自动用新 Cookie 重试。

如果主站 SSO 不可用，仍可在配置里手动填写游戏 Cookie 兜底（该值优先级最高）。

## 配置项

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | 关闭 | 插件总开关 |
| 立即执行一次 | 关闭 | 保存配置后延迟 3 秒跑一轮，便于验证 |
| 登录失效时通知 | 开启 | Cookie 失效只在连续失败期间提醒一次，不每轮刷屏 |
| 执行周期 | `*/5 * * * *` | 每轮先挪车再停车 |
| 停满多少分钟挪走 | `10` | 游戏规定最少停 10 分钟才允许挪走，填更小的值按 10 分钟计 |
| 最多同时停放车辆数 | `1` | 同时停放越多收益越高，但被贴条风险也越大 |
| 金币足够时自动买车 | **关闭** | 见下方「自动买车与自动以旧换新」 |
| 差价足够时自动以旧换新 | **关闭** | 见下方「自动买车与自动以旧换新」 |
| 游戏 Cookie | 空 | 一般无需填写。留空时自动用「站点管理」的主站 Cookie 换取游戏会话；仅在主站 SSO 不可用时才需要手动粘贴 `qcw.tangpt.top` 的 Cookie |

## 每轮执行逻辑

1. 解析登录 Cookie：手填值 > 未过期缓存 > 现走一次主站 SSO。
2. 读取游戏状态，失败时清除缓存并按「登录失效」处理（连续失败只通知一次）。
3. **自动买卖**（两个开关都关闭时这一步直接跳过，不产生任何请求）：
   先以旧换新、再买车，每轮**至多换一辆、买一辆**。买卖完成后重新读取一次状态，
   让新买/刚换上的车在同一轮就停出去。
4. **挪车**：遍历名下所有停车中的车辆，停够设定时长的调用 `unpark.php` 结算收益，释放出的车辆立即回到空闲池。
5. **停车**：把空闲车辆按每分钟收益从高到低，依次停到他人空闲的私家车位；目标车位在候选集中随机挑选，避免长期压在同一位车主身上。

目标车位筛选条件：不属于自己、没有车、且不是爱心车位。

## 自动买车与自动以旧换新

两个开关**默认都是关闭的**，因为它们会真实扣除金币，需要你自己确认之后再打开。

- **金币足够时自动买车** —— 在「等级买得起 + 金币买得起 + 车库没满」的车型里，
  挑每分钟收益最高的那辆买一辆。名下**一辆车都没有**时也会执行，能帮你自动补上第一辆车。
- **差价足够时自动以旧换新** —— 从你名下的**空闲**车辆里，挑每分钟收益最低的那辆，
  在「更贵、收益更高、等级够、补的差价不超过当前金币」的车型里，换收益涨幅最大的一辆。
  注意门槛按**差价**算，不是新车全价——以旧换新时旧车已折价抵掉大半。

设计上有三道限制，避免一夜之间把金币抽干：

- **每轮至多换一辆、买一辆**，不会一次性花光；
- **只动空闲车**，不会把正在赚钱的车换掉；
- **不动限时/限量车**：这类车不可再生，换掉就买不回来，需要的话用 `/换车` 手动处理；
- **必须有正收益**：只换更贵且每分钟收益更高的车，没有划算的就不动。

买卖排在挪车/停车之前执行，这样刚买的车当轮就能停出去赚钱。
每次自动买卖都会在页面顶部的「自动操作」一行留痕，例如
`自动以旧换新：奥拓 → 奔驰C，补 400 金，每分钟收益 +19`。

## 规则要点

- 停在别人私家车位超过 5 分钟，车位主人可以贴条；此时收益按 70% / 30% 分给车位主人和停车者。
- 单车位收益上限 3000 金币，停满 10 分钟才允许挪走，超过 12 小时未挪走会被系统自动清理。

## 界面

**插件详情页**（插件列表 → 不可躺自动抢车位）顶部是账户头卡与四个指标块
（今日收益 / 金币 / 待结算 / 距下次运行），下面一排按钮把内容分成**互斥的三页**——
点哪个就只显示哪一页，当前页签高亮，选择在重启后仍然保留：

| 区块 | 内容 |
| --- | --- |
| ① 我的车位 | 每个车位当前被谁占用，空闲则显示「空闲」。私家车位被他人停用超过 5 分钟后对方才能贴条，收益按 70% / 30% 分成。附「怎么操作」说明 |
| ② 车市 | 限时限量特卖、全部车型（按价格升序，标注每分钟收益 / 等级要求 / 你已拥有数量）、以旧换新候选，见下方「车市」 |
| ③ 我的车库 | 名下每辆车的 车型 / 金每分钟 / 状态 / 已停分钟 / 待结算金币。停车中的排在前面，按每分钟收益从高到低；「待结算」是挪车时能拿到的预估金币（已按单车位 3000 上限封顶），配对的就是 `/挪车 序号` 的序号。附执行历史表 |

切换按钮是**服务端驱动的真切换**，不是前端动画：按钮节点上声明了
`events.click`，渲染器把点击打成 `POST /api/v1/plugin/ParkingBot/tab`，
请求完成后渲染器自动重新拉取 `plugin/page/{ParkingBot}`，
服务端记住当前页签，于是页面只下发选中的那一个区块。

**主面板状态卡** —— 主仪表盘上会多一块卡片，显示昵称等级、金币、停车中数量和待结算金额。

以上数据来自每轮执行结束时落盘的账户快照，打开页面不会再去请求游戏接口，因此翻页很快、也不会因为游戏暂时不可达而白屏。

## 车市

插件详情页「② 车市」区块包含三组买卖操作，数据全部来自游戏车市（`game_data.php` 的车型表与
`flash_sale.php` 的特卖列表），每轮执行结束时随快照一起刷新。

- **限时 / 限量特卖** —— 显示折扣价、原价划线、每分钟收益、等级要求，
  以及剩余时间或剩余库存。售罄与等级不足的场次按钮置灰。
- **车市** —— 按价格升序列出全部车型，标注每分钟收益、等级要求与你已拥有的数量。
  金币不足、等级不够或车辆已满时按钮置灰并给出原因。
- **以旧换新** —— 列出你名下所有**空闲**车辆，每辆给出最多 3 个可换的更贵车型，
  按补价从低到高排列，按钮直接写明「换 <车型>（补 N 金）」。

### 关于操作按钮

**车市与车库里的买卖/挪车按钮点不了。** MoviePilot 的页面 JSON 是声明式渲染，
Vuetify 插槽类组件承载文本会渲染成空壳，之前的「立即挪车」等按钮只是长得像按钮。

不过渲染器支持在节点上声明 `events`，点击会发请求并自动重新拉页——
顶部那三个区块切换按钮就是这么实现的。除它们之外，操作走下面两种方式。

#### 方式一：远程命令（任何渠道都可用，含微信）

| 指令 | 说明 |
| --- | --- |
| `/车库` | 查看车库、停车时长、买得起的车型 |
| `/挪车 序号` | 立即挪车结算，序号取自 `/车库` 的列表 |
| `/挪车 车辆ID` | 同上，也可直接传 ID |
| `/买车 车型ID` | 买车，车型 ID 见插件页车市 |
| `/换车 旧车ID 新车型ID` | 以旧换新，旧车必须空闲 |
| `/抢购 场次ID` | 抢购限时/限量特卖车 |

`/挪车` 的序号与插件页车库卡片的序号是同一套排序口径（停车中的在前，
其次爱心车位、空闲，同组按每分钟收益从高到低），不会出现对错位的情况。
序号只接受自己名下确实存在的车，输错或传了别人的车 ID 会被直接拒绝。

#### 方式二：消息按钮（Telegram / Slack 等支持回调的渠道）

发 `/车库`，消息里会直接带**可点的按钮**——点「挪走 保时捷911」即可结算，
执行完自动刷新菜单。按钮回调数据格式为 `[PLUGIN]ParkingBot|unpark:<车辆ID>`，
由 `MessageAction` 接住。

微信等不支持按钮回调的渠道看不到按钮，但用上面的指令一样能操作。

#### 底层接口

四个后端接口都独立可用：

| 接口 | 参数 | 说明 |
| --- | --- | --- |
| `POST /buy_car` | `car_id` | 买车 |
| `POST /trade_in` | `old_car_id`, `new_car_id` | 以旧换新 |
| `POST /buy_flash` | `sale_id` | 抢购特卖车 |
| `POST /unpark` | `car_id` | 立即挪车 |

均已声明 `response_model`（`ApiResult`），响应结构可在 `/docs` 查询。
**响应必须是宿主要求的三键信封** `{success: bool, message: str, data: {...}}`——
前端 axios 拦截器会校验"恰好三个键、success 是布尔、message 是字符串"，
少一个键或 message 为 null 都会被判成 invalid-envelope，页面直接弹
「服务器返回了无效响应」，哪怕后端返回的是 200。
POST 参数用 Pydantic 模型收（走 JSON body）；写成标量会被 FastAPI 当成查询参数。
**等级、金币、车辆上限、旧车归属与空闲状态都由后端复核**，页面上的置灰只是提示。

## 注意

- 本插件只做自动停车与自动挪车，**不会**自动贴条或举报他人车辆。
- 「自动买车」「自动以旧换新」两个开关会**真实扣除金币**，默认关闭；打开前请先用 `/买车`、`/换车` 手动试一次，确认判定逻辑符合你的预期。
- 挪车时间依赖 MoviePilot 时区，请确保「设定 → 常规设置」里的时区与游戏页面显示的时区一致，
  否则停车时长会算错。
- 自动操作第三方站点可能与该站点的使用条款冲突，请自行评估后使用。
