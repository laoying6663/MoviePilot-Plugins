# 不可躺自动抢车位（ParkingBot）

自动把车停到他人私家车位赚金币，停够时长后自动挪车结算。
登录身份复用 MoviePilot「站点管理」里 `tangpt.top` 已保存的 Cookie，不用另外维护登录态。

## 使用前提

1. 在「站点管理」中登录 `tangpt.top`。
2. 账号在游戏站至少有 1 辆车（也可以开启「自动买车」让插件代买）。

## 配置项

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | 关闭 | 总开关 |
| 执行周期 | `*/5 * * * *` | 每轮先挪车、再停车 |
| 停满多少分钟挪走 | `10` | 游戏规定最少 10 分钟 |
| 最多同时停放车辆数 | `1` | 越多收益越高，被贴条风险也越大 |
| 自动买车 | **关闭** | 会真实扣金币；买满车辆上限后插件会**自动把它关掉** |
| 自动以旧换新 | **关闭** | 会真实扣金币 |
| 登录失效时通知 | 开启 | 不每轮刷屏 |
| 游戏 Cookie | 空 | 一般留空即可 |

## 每轮做了什么

1. 挪车：停够时长的车结算收益，释放回空闲池
2. 换新：挪完之后，把刚空出来的车往上换（以旧换新要求旧车空闲）
3. 买车：新买的车当轮就停到车位上
4. 停车：空闲车按收益从高到低，停到他人空着的私家车位

> 自动以旧换新排在挪车之后，是因为游戏要求旧车必须空闲——刚挪完的车正好变空闲，
> 排在挪车之前的话上一轮停着的车都还「停车中」，根本换不动。

## 两个花钱开关

默认都是关的，打开前建议先用聊天指令手动试一次。

- **自动买车** —— 在等级、金币、车位数都达标的车型里，买每分钟收益最高的一辆。
  **车辆买满 `MAX_CARS` 后，插件会把这个开关自己关掉**并通知你一次。
  满员之后游戏必然拒绝买车，留一个亮着的开关只会让人以为插件还在买，
  所以直接关掉是对现状的如实反映。
  **只关不自动开**：车位数是靠卖车、换新这些操作变化的，什么时候重新开由你决定 ——
  插件擅自打开一个会真花钱的开关，风险比关掉大得多。
- **自动以旧换新** —— 每次挪车之后执行：拿这轮刚挪完、刚变空闲的车去换，
  换成差价付得起且收益更高的车型。**不受车辆满员影响**（换新是 1 换 1，不占车位）。

保险措施：每轮至多一辆；只动空闲车；限时限量车不参与（不可再生，换掉就买不回来）；必须有正收益才换。

## 界面

详情页顶部一排页签，**点哪个只显示那一页**，选择会记住：

- **我的车位** —— 被占用的车位显示停车人、车图、已停时长与预估收益；空闲位显示斜纹底，
  并带一个「设为爱心车位」按钮（点一下把自己的空车位切成公益位，其他玩家停车给你贡献经验；
  再点一次恢复成按分钟产金币的私家车位）。车位卡高度统一，不会一高一矮
- **车市** —— 与游戏网页版一致：顶部按车型分类筛选，卡片显示车图、🪙 价格、每分钟收益、已拥有几辆，底部「购买」「以旧换新」都是可直接点的按钮（会真实扣金币，置灰即点不动）

### 车市两个按钮的禁用原因不一样

「购买」和「以旧换新」灰掉的原因**互不相干**，卡片上会分别说明：

| 按钮 | 灰掉的原因 | 提示文案 |
| --- | --- | --- |
| 购买 | 名下车辆已满，需要一个空车位 | `购买需有空位（已满 N 辆）` |
| 购买 | 金币不够 | `还差 X 金` |
| 以旧换新 | 名下一辆车都不空闲 | `所有车都停着，先挪一辆出来就能换` |
| 以旧换新 | 有空闲车但都比它便宜 | `没有更便宜的空闲车可换` |

**车辆满员并不会挡住以旧换新** —— 换新是 1 换 1，不占车位，游戏侧
（`showSelectTradeCar`）从头到尾也只看 `status === 'idle'`，不看车辆上限。
满员时如果换新按钮灰了，那一定是没有可用的空闲车：到「「我的车库」」把一辆车
挪出来（凑满时长后点「立即挪车」，或发 `/挪车 序号`），换新就又能用了。
同时成立的原因会一并显示，不会只留一条。
- **我的车库** —— 每辆车的收益/状态/已停时长；卡片底部有两个**真按钮**：
  停车中的车给「立即挪车」（绿底，点一下就结算收钱），闲置的车给「立即停到他人车位」
  （白底带金币，点一下就开停），副标题会告诉你「当前已停 N/上限」；
  区块顶部还有一个「立即刷新状态」按钮，见下
- **数据统计** —— 每日收益与支出（买车 / 换车差价）、每小时分布、每日明细，保留 60 天。
  收益里单独拆出「其中贴条」，一眼看出贴条到底赚了多少；
  手动点「贴条」和自动贴条的收入都会记进这一项，点完立刻落盘（不用等下一轮定时任务）；
  收入字段兼容游戏 2026-10 的改名（ine → ownerEarn），两版都认；
  每小时收益画成**折线图**，峰值点常显金额胶囊，图下有摘要行，
  **鼠标悬停**任意时段会显示该时段的具体金额
- **响应速度**：手动贴条、爱心车位切换都走并行取数（状态 ‖ 车型表 ‖ 市场数据一起拉），
  游戏站单请求约 1.1 秒，点击后的等待从 8.8 秒压到 3.3 秒，和手动挪车同一量级

## 称号

顶部名字旁边的称号标签可以直接点开选择器换称号，和游戏里点顶栏一样；
只列已获得的称号，「取消佩戴」也在列表里。换称号只改显示的名字，不影响收益。

## 经验值

顶部名字旁边的等级格里显示当前等级和本级经验进度，点一下展开详情面板，版式和游戏网页版的弹窗一致：

- **常显的一格**：`等级 Lv.7` 同一排，下面跟一条细进度条和 `2,285/2,500`（本级已得 / 下一级门槛）
- **展开后**：当前等级、总经验 / 下一级门槛、进度条百分比、还差多少经验升级，
  以及今日各项经验获取的已得 / 上限（停车、贴条、举报、买车、以旧换新、爱心停车、爱心车位收益）
- **默认折叠**，点一下才展开；展开后右下角有「收起」

进度百分比按**本级起点**算：`expReq` 是累计门槛，显示的是
`(当前经验 − 本级门槛) ÷ (下一级门槛 − 本级门槛)` —— 直接拿当前经验除以下一级门槛会算出 91%，
和游戏里的 73% 对不上。

各来源的每日上限取自 `game_data.php` 里 `expConfig` 的 **`xxxDailyLimit`**
（停车 150 / 贴条 90 / 举报 100 / 买车 300 / 以旧换新 300 / 爱心停车 50 / 爱心车位收益 200）。
注意 `park` / `ticket` 那组键是「单次动作给多少经验」，不是上限，别混用。
`levelTable` 和 `expConfig` 都只在 `game_data.php` 里，`state.php` 不返回，
所以它们跟着车型表走同一份缓存 —— 经验值面板不会多发任何请求。

取不到今日经验时显示 `—/上限` 而不是 `0/上限`：没数据不等于真的是 0，
但上限本身是确认的，照样显示出来。

## 通知铃铛

顶部名字旁边的铃铛（游戏顶栏同一位置），点开看游戏的消息通知：

- **角标**：每轮定时任务顺带拉一次未读数（`?count=1`），挂在铃铛上，超过 99 显示 `99+`；
  没未读就不显示，不会显示一个 `0`。这一趟是**并行**跟着特卖 / 称号一起发的，不额外多花时间。
  这一轮接口没拉通时沿用上一次的数，而不是写成 0 —— 后者会让角标在一次网络抖动后凭空消失
- **列表**：点开的当刻才去拉（`?perPage=50`），不点就不拉。默认折叠，展开后右下角有「收起」，
  再点一次重新拉，避免隔半天再打开看到旧数据
- **只显示最近 8 条**：50 条通知铺开近 3000px，手机上要划十几屏。
  面板只渲染最近 8 条，底部有一行「仅显示最近 8 条，还有 N 条，回游戏网页看全部」——
  不静默截断，否则会让人以为游戏侧没发过通知。
  拉取条数仍是 50 不动：全部记录都参与算「N 条未读」，砍拉取条数等于把那个数字的上限也砍了
- **取数**：`notifications.php?perPage=50&category=all`。`category` 是游戏那边每次都带的参数，少带可能返回空数组。
  这个请求和 `state.php` **并发**发出（两者互不依赖），所以点开铃铛只等一个来回而不是两个
- **版式**：和游戏弹窗一致 —— 类型标签按 `notify_type` 配色（贴条红、升级金、买车绿……），
  未读的左边多一条亮色竖条，时间显示成「3分钟前 / 5小时前 / 2天前」，超过 7 天显示具体日期。
  游戏以后新增通知类型时，未知类型照样显示内容，只是没有专属配色。
  （游戏 `notifications.php` 的 `created_at` 下发的是 **UTC**，而 `state.php` 的
  停车时长是**本地时间** —— 两个端点口径不一致，插件各自按各自的口径换算，
  不然面板会把「刚刚」显示成「8小时前」。）

### 停车时长用的是哪个时间字段

游戏返回的停放时刻有两个字段，插件**优先用 `parkedTimestamp`**（epoch 毫秒），
没有才退回 `parkedTime` 字符串。这和游戏前端自己的算法一致：

- 车：`uc.parkedTimestamp || new Date(uc.parkedTime).getTime()`
- 车位：**只用** `spot.parkedTimestamp`

时间戳是绝对时刻，不受服务端时区配置影响；字符串则要靠猜 —— 上面那条通知时间
就是例子。与其猜，不如用游戏自己给的权威字段。
- **跨轮次保留**：定时任务每 5 分钟重写一次快照，插件会把已拉到的列表一起带过去，
  不会因为跑了一轮就变回「暂无通知」
- **全部已读**：底部有「全部已读」按钮，调游戏 `action=read_all`，成功后角标和列表立刻更新。
  没有未读时这个按钮不出现、也不会空发请求。游戏侧若不接受（返回里带 `error`），面板保持未读不动，并在「最近一轮」写明原因 —— 不会假装已经读过

> **清空通知插件不提供**。它会真的删掉游戏里的通知且不可恢复，而插件页弹不出
> `confirm` 二次确认框（渲染器没有 JS 执行口），误按一下没法挽回。要清回游戏网页上点，
> 那里既有确认框也有确认按钮。

## 登录失败时日志怎么看

插件走主站 SSO 换取游戏会话（游戏是独立子域，主站 Cookie 不足以通过 `state.php` 鉴权）。
失败时日志按顺序打这几行，**从上往下读就能定位到断在哪一环**：

| 日志行 | 说明什么 |
| --- | --- |
| `主站 SSO 跳转链（共 N 跳）` | 每一跳的状态码、URL、下一个 Location、这一跳新种了哪些 Cookie 名 |
| `SSO 走过的域名` | 有没有真的跳到 `qcw.tangpt.top`；没到的话会直接点名 |
| `本次带上的 Cookie 名（不回显取值）` | 主站 Cookie 有没有被换成游戏会话 Cookie（**只记名，不记值**） |
| `换到 Cookie 后回游戏验证失败 —— …` | `state.php` 到底返回了什么形态 |

最后一行会把返回形态分开说，因为它们要查的东西完全不同：

- **state.php 无响应（连不上或超时）** → 查网络 / 目标站可达性
- **请求 state.php 抛异常 TimeoutError: …** → 同上，超时秒数也在里面
- **疑似 HTML 页面（多半是登录页 / 风控拦截页）** → Cookie 没被游戏站认下；
  可能是主站会话过期，也可能是风控拦了。日志里会给出响应开头的前 120 字
  （超过 24 位的连续 token 已替换成 `<长串已隐去>`，不会泄漏）
- **state.php 返回 JSON 但 success 非真** → 游戏明确回了 `error`，原文照抄
- **state.php 返回的不是 JSON / 返回空内容** → 中间有代理或网关在中间插手

拿到的 Cookie 无论是否可用**都不会缓存**，坏 Cookie 不会反复用。

## 规则要点

- 停别人车位超过 5 分钟，车位主人可以贴条，此时收益按 70% / 30% 分成。
- 单车位收益上限 3000 金；停满 10 分钟才允许挪走；超过 12 小时未挪会被系统清理。

## 注意事项

- 挪车时长依赖 MoviePilot 时区，请确保「常规设置」里的时区与游戏页面一致。
- 本插件不自动贴条或举报他人车辆。
- 自动操作第三方站点可能与该站点使用条款冲突，请自行评估后使用。

## 插件图标

市场页的图标取法在前端 `MoviePilot-Frontend/src/components/cards/PluginCard.vue` 里写死了，
只有两条路：

```js
if (plugin_icon?.startsWith('http'))  return getProxyImageUrl(plugin_icon, ...)  // 后端代拉
return `./plugin_icon/${plugin_icon}`                                                // nginx 本机静态目录
```

所以：

- **写完整 URL**（本插件现在的做法）→ 走 MoviePilot 后端的图片代理
  `/api/v1/system/img/{proxy}?imgurl=…`，由后端去拉这个地址。图标跟着仓库走，
  不用往 MoviePilot 主机上放任何文件
- **只写文件名** → 拼成 `./plugin_icon/<文件名>`，由 **nginx 直接读本机静态目录**
  （响应头 `Server: nginx/1.26.3` + `ETag` + `Last-Modified` 就是本地静态文件的特征）。
  这个目录**不会**从 GitHub 仓库自动同步，把文件传到仓库 `icons/` 对它没有任何作用

仓库里的 `icons/Parking_A.png` 是给第二种方式准备的存档（原始设计稿 `Parking_A.jpg` 同理）；
第一种方式靠的也是这个地址，只是由后端去拉。

## 车库里的两个按钮

「「我的车库」」每张卡片底部有两个**可以直接点**的按钮，一眼能分出方向：

| 按钮 | 外观 | 什么时候出现 | 点了做什么 |
| --- | --- | --- | --- |
| **立即挪车** | 绿底白字 | 停车中且已停够 `MIN_PARK_DURATION` | 调 `unpark.php` 结算，收益进当日统计 |
| **立即停到他人车位** | 白底深字 + 金币 | 车辆空闲，且存在他人的空余私家车位 | 从他人空余私家车位里挑一个停过去（优先高场景加成，见下） |

两个按钮的条件不满足时都是**灰态且不挂事件** —— 页面上按下去是真的没反应，
不会空发请求再弹一句错误：

- 没停够时长的车显示「还需 N 分钟」
- 别人没有空余私家车位时显示「暂无可停车位」
- 空闲车的挪车按钮不出现可点态（没停的车本来就挪不动）

时长的最终把关仍在后端做一遍（`api_unpark` 会重新取一次游戏状态），
所以绕过界面直接调接口也挪不走没停够的车。

## 手动操作为什么这么快

游戏站单次请求约 1.1 秒，几个请求串起来就是好几秒的等待。所以插件把**互不依赖的
请求都并行发了**：

| 操作 | 串行耗时 | 现在 | 怎么做到的 |
| --- | --- | --- | --- |
| 立即停车 | 2.2 秒 | **1.1 秒** | `state.php` 和车型表没有依赖，并行拉 |
| 立即挪车 | 5.5 秒 | **3.3 秒** | 特卖/称号的拉取提前挂上，和挪车请求同时跑 |
| 立即刷新状态 | 3.3 秒 | **2.2 秒** | 同上 |

并发只改变「什么时候发请求」，不改变「拿到什么」——落快照拿到的特卖和称号与串行
完全一致；某个接口失败会退回单独拉取，不会把整个操作带崩。

> 页面渲染本身一直很快（0.2~0.4 毫秒），瓶颈从来不在那里，所以没有去优化它。

## 车型表更新

车型表和分类都是**运行时从游戏接口拉的**，插件里没有写死任何车型名或分类名，
所以游戏上新车（比如 2026-10-14 一次从 4 个分类加到 9 个，新增传奇车这种
要 Lv.15、价格 916.5K 的车），插件这边**不用改代码**。

车型表在进程内缓存 **1 小时**，到点自动重取。想立刻按最新数据来一遍，
在插件设置里点一次保存（会触发重载、清空缓存），或者重启 MoviePilot 即可。

> 拉取失败时不会把空表写进缓存，下一轮还会重试，不会因为一次网络抖动就
> 固化成「没有车型表」。

## 车库顶部的「立即刷新状态」

车库区块顶部左边是刷新按钮，右边写着数据有多旧，比如「3 小时 9 分钟前更新」。
点一下刷新按钮会重新拉一次游戏状态，停车时长、收益、待结算、车位情况全部换成刚拉到的数，
右边那句也跟着变成「刚刚更新」。

**刷新只读状态，不挪车也不停车** —— 想挪车点卡片上的绿「立即挪车」，那是另一回事。
刷新也不会在「最近 10 轮」里多出一行 `0 / 0 / 0` 的噪声记录。

### 为什么不是自动刷新

MoviePilot 的插件详情页用的是声明式 JSON 渲染器
（前端 `MoviePilot-Frontend/src/components/render/PageRender.vue`），
它只认 `component / props / events / text / content / html` 六个字段，
**没有任何定时器**；`events` 也只在用户点击时触发。所以页面不会自己跳，
JSON 模式下无论怎么写都做不到「每 N 分钟自动重绘」—— 这是宿主前端的能力边界，
不是插件漏配了什么。

真要自动重绘只能改成 Vue 联邦远程组件模式，由插件自己写 `setInterval`，
代价是现有页面整体重写。本插件选择用「刷新按钮 + 数据新鲜度提示」，
把选择权交给你：默认按「执行周期」每 5 分钟更新一次快照，
需要更实时的时候点一下即可。

## 手动停车的额外说明

不想等定时任务、想立刻把闲置的车开出去赚金币时，在「「我的车库」」点一下即可：

- **只对闲置车有按钮**；停着的车不能重复停
- 车位由插件从**他人的空余私家车位**里挑一个（自己名下的车位、爱心车位、已占的车位都不选），
  选择规则是**优先场景加成高的**，见下节
- 别人没有空余私家车位时，按钮是灰的，按下去没反应，**不会**空发请求
- **手动点击不受「最多同时停放车辆数」限制** —— 那个上限只约束定时任务。
  车库副标题里的「当前已停 N/上限」只是给你看行情的，要不要超、停几辆，你自己判断
- 手动停车不产生额外记账，也不占用执行轮次；收益照常由游戏侧结算，
  停够时长后在车库点「立即挪车」或发 `/挪车 序号` 都能结算

## 场景加成

游戏新上了「场景加成」：买了带加成的停车场场景（街道夜景 +2%、沙滩/牛来！！+5%，
后两个 5000 金币）之后，**把车停进这个车位的人**每分钟多拿一点。
游戏规则原文是「最终收益 = 基础收益 + 基础收益 x 加成百分比」——
也就是**先按每车位 3000 封顶，再乘加成**，5% 车位的实际上限是 3150。
爱心车位不受影响。

插件这边做了两件事：

- **停车优先去加成高的车位**。定时任务挑车位时先按车位主人的场景加成从高到低排，
  同一档内仍然随机（保留原先「别把车长期压在同一个人身上」的意图）。
  同时加了**每个车位主人名下最多停 1 辆**的硬上限 —— 5% 场景要 5000 金币，
  全服买的人可能就两三个，不设上限的话你名下所有车会全压过去，
  那个人一眼就能看到「他所有车都在我这儿」，批量驱离和举报都不用挑目标。
  撞上限的车位会让给下一个高加成的人。
- **「我的车位」标题右侧显示自己的加成**（`收益+5%` 这块金色的标），
  和游戏网页版的画法一致。没有加成（默认场景）时不显示。

### 每家只能停 1 辆之后，车会变少

上限收紧到 1 辆之后，**停 N 辆车就需要 N 个不同的车位主人**。
主人不够时插件会少停几辆，钱自然也少 —— 这是这条上限的真实代价。

插件会把两种「停不进去」分开写在日志里，别再混为一谈：

- 「当前没有可停的他人空余车位」：一个空位都没有
- 「还能停 N 辆，但剩余 M 个候选车位都归 K 个已停满 1 辆的车主」：**车位是有的，只是主人重复了**

> v1.52.1 修过一个这里的 bug：上面第二句原来恒打印成
> **「候选车位只剩 0 个、都归 0 个车主」** —— 因为统计用的是那个
> `while targets:` 循环**已经 pop 空**的列表。等于在自己说自己没被卡住，
> 比不写还误导。现在改成在循环里就地统计被挡住的候选。

页面快照里 `free_private_owners` 就是「有多少个**不同的**主人还有空闲车位」，
`free_spots` 是「有多少个空车位」。**决定能停几辆车的是前者** ——
一个人名下 3 个车位全空，`free_spots` 算 3，但每家只能停 1 辆时实际只能用 1 个。

> 场景数据来自 `game_data.php` 的 `parkingBackgrounds`，玩家的场景 id 在
> `state.php` 的 `users` 里，两份都已经在拉了，不额外发请求。
> 取不到时按 0% 处理，行为和这个功能上线之前完全一样。

## 个性化（场景 / 皮皮秀）

详情页第 5 个页签，把游戏里分开放的**场景店**（停车场背景）和 **show 场**
（皮皮秀 / QQ 秀）合并成一个分类，页内可以切「场景 / 皮皮秀」两个子页。

- **商品和价格直接读游戏接口**，不额外抓页面：目录读 `game_data.php` 的
  `parkingBackgrounds` / `qqShows`（和车型表同一份响应、共用那个 1 小时缓存），
  已购与使用中读 `state.php` 的 `ownedBgs` / **顶层** `currentBg` /
  `ownedQqShows` / `users[我].qqShowId`。列表是遍历接口返回的整个数组，
  游戏以后上新场景或新皮皮秀会自动出现，不需要改代码。
- **四种状态一眼区分**：使用中（金色角标）、已拥有（青色「✓ 已购买」，
  可切换）、未购买（显示价格）、金币不足（红色「还差 N 金」，按钮置灰）。
- **场景卡带「收益 +N%」角标**：买贵场景的意义就是让自己车位对别人更有吸引力。
- **皮皮秀按性别过滤**：接口给的是全部 16 款，页面只列匹配自己性别 + 通用款，
  和游戏 show 场的规则一致；再点当前穿戴款会恢复该性别的免费默认款。
- **购买走游戏自己的通道**：场景打 `buy_bg.php`（服务端校验并扣钱）；
  皮皮秀**没有独立购买接口**，按游戏前端 `selectQqShow` 的做法改
  `cash` / `qqShowId` / `ownedQqShows` 后 `saveState()` 全量回写。
  插件会**先重新拉一份最新 state 再改**——state.php 的 POST 是全量覆盖，
  拿快照里的旧数据回写会把刚停车/挪车的结果整份盖掉。
- 图片只存**直链**（`https://qcw.tangpt.top/assets/...`），不下载到本地；
  游戏站加载不出来时退化成名字首字，不会破版。

### 时间一律按北京时间，经验每日 08:00 重置

**插件自己产生的时间全部是北京时间**：统计页按天分桶、页面上的时间戳、
「已停 N 分钟」、定时任务的下次触发点，都走 MoviePilot 配的时区。

**只有一处内部碰 UTC** —— `_exp_daily`。因为游戏拼 `dailyExp` 键用的是
`new Date().toISOString().split('T')[0]`（`toISOString()` 永远是 UTC），
服务端写进去的键尾就是 UTC 日期。插件必须按 UTC 去匹配，否则北京时间
00:00~08:00 之间一个都匹配不上，七行会**全部**变成「—/上限」，而且只在夜里犯，
很容易被当成偶发抽风。

**换算成北京时间就是「每天 08:00 换日」**（北京 = UTC+8，中国无夏令时）。
这个时刻已经写进界面：等级详情面板底部和刷经验那行都会显示
「每日经验在 08:00（北京时间）重置」—— 不写出来的话，凌晨看着「今天还早」，
进度条早上就清零了，只会以为插件算错。

> ⚠️ **别把它改成「北京时间减 8 小时」**。那在宿主时区恰好是 UTC+8 时等价，
> 一旦 MoviePilot 配成别的时区就悄悄算错日期，「今日经验」整片变「—」。
> 正确做法是**按 UTC 取日期算，界面和文案一律用北京时间表述**。

**统计页的「当日收益」仍然按本地 00:00 分桶**（没有跟着挪到 08:00）。
所以拿统计页的某一天去对经验面板的同一天，差 8 小时 —— 这是有意保留的：
「今天赚了多少」按自然日看更符合习惯，而经验上限本来就只能按游戏的 08:00 算。

### 经验值面板的另外两个口径

**今天没拿过的一项显示 0**：游戏那边是 `dailyExp[key] || 0`，键不存在也当 0，
插件跟着。只有**整份 `dailyExp` 压根没拿到**时（接口失败 / 结构变了）才显示
「—/上限」—— 那时候显示 0 等于撒谎说「你今天一分没拿」。两者别搞混。

## 优先停爱心车位赚经验

配置里有一个开关，**默认关闭**：

- **优先停爱心车位赚经验**：打开后，定时任务优先把空闲车停到**别人**的爱心车位上，
  赚的是**经验**而不是金币 —— 进度就是等级详情面板里「爱心停车」那一行。
  **爱心停车经验达到当日上限后**，这些车会自动挪回来，转去普通车位赚金币，
  不会一直占着车位不产钱。

> ⚠️ **停在爱心车位不产金币**。开着这个开关等于主动把一部分收益方式从「赚金币」
> 换成「赚经验」，金币收入会明显下降。它默认关闭就是为了让你自己决定什么时候换。
>
> 进度判定和等级详情面板**完全同源**：已得读 `state.dailyExp` 的 `charity_park`，
> 上限读 `game_data.expConfig.charity_parkDailyLimit`（后端没给就是 50）。
> 两处不同源就会出现「面板显示没满、车却已经不去停了」这种自相矛盾。
>
> 每个车位主人名下最多停 1 辆这条上限**对爱心车位同样生效** —— 全服开了爱心车位
> 的人未必多，不设限的话车会全挤在同一个人那儿。

## 自动刷购车 / 以旧换新经验

配置里有一个开关，**默认关闭**：

- **自动刷购车 / 以旧换新经验**：每轮做一次
  「买最便宜的车 → 补差价换成次便宜的 → 回收换来的那辆」，
  把等级详情面板里「购车」和「以旧换新」两项的每日经验刷到当日上限，
  **刷满即停**，之后照常停车赚钱。

实测这两项的量级差很多：购车 +100/次、上限 300（3 次刷满）；
以旧换新只有 +30/次、上限 300，**要 10 次**。所以以旧换新才是大头。

### 它会回收一辆车，这是不可逆的

游戏的买车和回收都要求车处于**空闲**状态，而你通常是满员的（MAX_CARS = 10），
所以必须先腾出位置，而腾位置**只能靠回收**。

- 车库满员时，插件会回收**一辆最便宜的空闲车**换回金币（约原价 80%）。
- 那辆车**不会自动买回来**，车队从此少一辆。
- 之后每轮循环结束时工位原样空出来，所以**只有第一次**会动你的车。

定时车里停着的车不会被回收：插件排在挪车之后执行，只有挪完变成空闲的才可能被选中。
限时车（`carId = 0`）也一律不碰 —— 卖掉就再也买不回来。

### 花费怎么算

单轮净支出 = **新车价 × (1 - 回收率)**。买最便宜的两辆最省，因为回收率是个固定比例。

**回收率以游戏实际下发的为准**，插件不写死：游戏前端
（`js/modules/api.js`）是 `if (cfg.RECYCLE_RATE) GAME_RULES.RECYCLE_RATE = ...`，
也就是说 `state.php` 的 `gameSettings.RECYCLE_RATE` **覆盖** `game_data.php` 的
`gameRules.RECYCLE_RATE`。只读后者拿到的是已经被覆盖掉的旧值。

真正记进统计的是 `recycle_car.php` **实际返回的** `recyclePrice`，
所以回收率再怎么调，「数据统计」里的收支都对得上。

> 数据统计页新增了「其中回收」卡片，回收拿回的钱按**收入**并进「当日收益」。
> 不记的话，刷经验这种只出不进的循环会让当日净收凭空少一大截。

### 别和「自动买车 / 自动以旧换新」同时开

**v1.52.2 起，插件会自动挡掉**：刷经验期间（两项经验还没满），
自动买车和自动换新整轮跳过，日志会写明原因。**经验刷满后自动恢复正常。**

为什么必须挡 —— 这不是「功能冲突」，是**真会烧钱**。真机记录（2026-10-17）：

```
bought    3        买了 3 辆奥拓（800）
diff  340500       = 3 × 113500，而 113500 + 800 = 114300 = 奥迪A8 的价
recycled 274320    = 3 × 91440 = 3 辆 A8 的回收价（80%）
净损失 68580，而设计里一轮只该净亏 400
```

原因是 `_auto_trade_one` 排在刷经验**之前**，而它挑的偏偏是
**每分钟收益最低的空闲车** —— 刷经验刚买的奥拓只有 6 金/分，
正好是最「便宜」的目标，被它抢先换成了收益最高的奥迪A8（49 金/分）。
`_auto_buy_one` 也有同一个毛病：刷经验末尾会把空位还回来，
它一看有空位就把工位买成 A8。

**买的还是那辆最便宜的车、经验照拿，钱全赔进去。**

### 买完之后怎么认出那辆新车

游戏前端买完车是直接 `loadFromServer` 重载状态的，**从不读响应里的车 ID**，
所以插件也不猜响应字段名，而是拿刷新前后的车辆实例 ID 做**差集**定位。

但差集有个前提：刷新时新车已经可见。**真机跑下来发现并不是**——
`buy_car.php` 已经写成功（新车实例 ID 里那串时间戳就是买的那一刻），
紧接着那一次 `state.php` 还没带上它。只试一次的话这一步永远推不下去，
结果是「每轮回收 + 买车」净亏 160 金币的死循环。

所以这里会**重试到看见为止**（3 次、每次隔 1.2 秒），代价是买完车库能立刻刷新。
真的还是认不出来时，日志会写明**实际匹配到几辆**，
摘要里也会说「这辆车留在车库」—— 那种情况请到「我的车库」确认后再决定要不要继续开。

## 爱心车位切换

「我的车位」页每个空闲车位下面有「设为爱心车位 / 恢复私家车位」按钮。点完之后页面
**立刻**变成切换后的样子，不用等下一轮定时任务。

原因是 `charity_spot.php` 已经返回成功、但紧接着那次 `state.php` 有时还读回旧值
（服务端写入延迟）—— 游戏网页版那边要等你刷新整页才看得到变化。插件的做法是：
先用服务端状态重���整份快照，**再**按本次操作把那个车位覆盖掉，顺序反了会被那份
仍旧是旧值的快照盖回去。下一轮定时任务拿真实状态覆盖回来，会自愈。

如果服务端读回来的值和本次操作不符，日志里会记一条 WARNING 留证。

## 车市怎么找车

全服 254 辆车，车市页顶部有一排**分类胶囊**（点一下就切到那个分类），第二排是这次
新增的工具条：

- **只看可买**（默认关）：只看**等级够得着**且**现金买得起**的车型。两个条件合在
  一个开关里 —— 用户真正要的是「点进去就能买」的那一批，分成两个开关反而更难用。
  副标题会写明当前条件下有几辆买得起。
- **排序**：**性价比**（每分钟收益 ÷ 价格，默认）/ 价格低→高 / 收益高→低。
  同样一笔钱能买到多少收益，这是买车时唯一真正要比较的量；只按价格排会把一堆
  便宜的老车顶到最前面，只按收益排又会全是不买得起的豪车。
  买不了的车（价格 0 的初始车）排在最后，不会靠「分母兜成 1」刷出虚高的比值。

这两个开关**都不记忆** —— 每次打开车市恢复默认（只看可买关、排序性价比）。
记住筛选状态反而容易让人忘了自己开着筛选而漏看车型。

> 说明：MoviePilot 的插件页渲染器只有 `events.click`，没有输入事件绑定。
> 所以「输入车型名搜索」在这个页面上做不出来（输入没有事件能触发）。
> 能做的只有上面这种点一下就整页重渲染的筛选/排序开关。
> 要按名字精确找车，用聊天指令 `/买车 车型ID`。

### 锁定换新：按分类只换指定车型

自动以旧换新原本每轮挑「收益增量最大」的那一辆，同一个分类里今天可能换 A、
明天换 B。想固定成「尊贵车只换迈巴赫」的话，在车市卡片上点**「锁定换新」**：

- 锁定粒度是**车型所属的分类**，不是单辆车。点某辆车后，它所在的整个分类
  只允许换这一款，其他分类不受影响。
- **不做「锁定款换不了就退而求其次」**——等级不够或差价不够时，这一轮直接不换，
  等条件满足。否则锁了等于没锁。
- 再点同一辆车的「已锁定」= 取消该分类的锁定；取消后恢复「挑收益最高」。
- 锁定状态存在 view 里（和当前分类、选旧车状态同一套），插件重启后仍在。
- 为什么不放配置表单：分类是游戏动态下发的（2026-10 一次从 4 个加到 9 个），
  表单没法预先列出这些分类名。

## 金币流水

「数据统计」页新增一张**金币流水**卡片，逐笔记录当天的每一笔收支：

| 类型 | 方向 | 说明 |

## 自动贴条

配置里有两个开关：
- **自动贴条**（默认**关闭**）：打开后，别人停在我私家车位上够规定时长、
  且预计罚款达到你设的门槛时，插件会自动贴条。
- **达到多少金币才自动贴条**：比较的是车位卡片上显示的那个「贴条收益」。
  填 `0` 表示不设门槛，所有停够时长、可以贴的车位都贴；想只贴高价值车位就填几百。

判定口径和手动贴条**完全一致**（同样的时长门槛、同样的分成比例、同样的排除规则）：

- 只贴**自己的私家车位**，爱心车位按游戏规则不贴
- 自己停自己车位上的车不贴
- 停不够 `MIN_TICKET_TIME`（游戏默认 5 分钟）不贴 —— 白发一个必然被拒的请求没意义
- 同一辆车在**同一个车位只贴一次**。游戏规则本来允许每 5 分钟再贴一次，
  但自动反复罚款容易招致报复，所以加了去重：那辆车开走后记录会被清掉，
  它再回来才算新的一次停放

每轮把所有满足条件的车位都贴了（收益高的先贴），**名额没有被你设的上限卡住** ——
你的私家车位就那么几个，阈值自然会控制数量。贴条失败的车位不会被记进「已贴」，
下一轮还会重试。

> 贴条会真实产生罚款收入进当日收益，但也可能让对方盯上你的车位。默认关着是刻意的。

## 贴条

「「我的车位」」里，别人的车停在你的**私家车位**上时会显示贴条按钮和**贴条收益**。

- 罚款 = 该车位的预估收益 × `TICKET_OWNER_PERCENT`（游戏默认 90%，你拿大头，对方拿剩下的）
- 停不够 `MIN_TICKET_TIME`（游戏默认 5 分钟）时按钮置灰，并显示还要等几分钟
- 爱心车位不给贴条；自己停自己车位上的车也不给
- 贴条是真罚款，会加进「当日收益」
