# 动态企微可信IP（自用版）

一个插件,只做一件事:**让企业微信应用的「可信 IP」和登录 Cookie 一直有效**。

定时检查本机公网 IP,变化时自动写回企业微信应用的「可信 IP」列表;同时把登录 Cookie 持久化到磁盘,
重启、更新插件都不丢。**通知本身交给 MoviePilot 内置的微信通知渠道**,本插件不重复实现一套。

> 插件 ID 仍是 `DynamicWeChatSelfUse`,配置前缀仍是 `dynamicwechatselfuse_`,
> 升级到 5.0.0 不会丢应用ID、Cookie 与通知渠道配置。

> **v5.0.0 变更**:移除 v4.0 并入的企业微信自建应用能力(通知推送、`/wecom` 回调、远程命令、控制菜单)
> 及其 11 个配置字段。详见下方「通知怎么发」。

> **本插件名为「动态企微可信IP（自用版）」，用于和插件市场上的同名官方插件区分，请勿混淆。**
> 本仓库是 [RamenRa/MoviePilot-Plugins](https://github.com/RamenRa/MoviePilot-Plugins) 中同名插件的独立维护分支,原始作者 RamenRa,原始创意来自 [suraxiuxiu/MoviePilot-Plugins](https://github.com/suraxiuxiu/MoviePilot-Plugins/)。
>
> 开发者交接文档（状态快照、权威数据源、机制说明、验收判据、红线清单、踩坑档案）见仓库根目录 [HANDOVER.md](HANDOVER.md)。

---

## 这个插件解决什么问题

企业微信应用只能从「可信 IP」列表里的地址发消息。家里宽带的公网 IP 一变,企微应用就发不出通知了——表现为「明明网络没问题,但微信收不到任何消息」。

本插件做的就是:每隔一段时间查一次公网 IP,变了就自动登录企微后台把新 IP 填进可信 IP 列表,你什么都不用管。

顺带解决第二个痛点:**Cookie 反复失效**。企微后台的登录 Cookie 是有时效的,原版插件只把它存在内存里,重启或更新插件就没了,必须重新扫码。本仓库的 3.x 版本把 Cookie 持久化到磁盘,重启和更新都不会丢。

## 安装

### 方式一:插件市场(推荐)

1. 进入 **系统 → 插件 → 插件市场**
2. 添加仓库地址:
   ```
   https://github.com/laoying6663/MoviePilot-Plugins
   ```
3. 刷新市场,搜索「动态企微可信IP」并安装
4. 安装后在插件列表里**重载一次插件**

> 市场拉取失败(日志报 `EndOfStream` / `所有策略均无法读取插件索引`)说明你的 MoviePilot 出站代理有问题,先解决代理再回来刷新,否则装不上新版。

### 方式二:手动放进容器

市场刷新不了时用这个,绕过索引直接覆盖代码:

```bash
# 把仓库里的 plugins.v3/dynamicwechatselfuse 目录拷进容器
docker cp ./dynamicwechatselfuse <容器名>:/app/app/plugins/DynamicWeChatSelfUse
```

然后在 MoviePilot 里**重载插件**或重启容器。

> 数据目录 `/config/plugins/DynamicWeChatSelfUse/` 与代码目录是分开的,更新插件不会动你的 Cookie 和配置。

## 快速开始

1. **填应用 ID** —— 打开企业微信管理后台的应用详情页,地址栏末尾那串数字就是应用 ID。多个应用用英文逗号分隔。
2. **配通知渠道** —— 在插件配置里勾选你已在 MoviePilot「设定 → 通知」中配置好的渠道(3.1.0 起支持多选,不用再手打 `WeChat` 这种名字)。至少配一个才能用 `/push_qr`。
3. **保存配置** —— 这一步不能跳过,配置要落库才会生效。
4. **扫码登录一次** —— 用面板里的「本地扫码修改IP」,或在企微应用里发 `/push_qr`。扫完 Cookie 就存下来了,之后重启、更新都不会再丢。
   - 扫码后若企业微信要求短信验证码,**详情页会自动弹出「短信验证码」输入框**(v4.0.2 起,平时不显示、需要时才出现),填 6 位数字点「提交验证码」即可。不需要配置企业微信消息回调,也不需要 AI 全局助手。
   - 备用通道仍保留:给企业微信应用发 `6位数字?`(如 `510010?`),或启用 AI 全局助手后发 `/wxcode 510010`。

## 配置项

| 配置项 | 说明 |
|---|---|
| **启用插件** | 总开关 |
| **应用ID** | 必填。企业微信应用 ID,多个用逗号分隔 |
| **检测周期** | 公网 IP 检查频率,crontab 表达式,默认 `*/10 * * * *` |
| **Cookie 保活周期** | 可选,crontab,默认 `*/10 * * * *`。**调长可降低被企微风控关注的概率**,见下方说明 |
| **通知渠道(多选)** | 3.1.0 起从 MoviePilot 已配置的渠道里勾选,支持微信、Telegram、Slack、钉钉、QQ 等 |
| **企业微信接收人 userid** | 可选。只推给指定成员时填,留空则发给该渠道所有已配置接收人 |
| **第三方通知 Token** | Server酱(SCT开头)、PushPlus、AnPush、IYUU 的 Token,多个用 `\|\|` 分隔 |
| **IP变动后通知** | Cookie 失效时不立即通知,等公网 IP 变动后再发。适合 IP 变动慢、Cookie 掉得快的环境 |
| **使用CookieCloud** | 见下方「CookieCloud」一节 |
| **Cookie(header)** | 高级。手工填入企微 Cookie,可作为 CookieCloud 不可用时的兜底 |

## 面板说明

插件面板上有两个数字,含义不同,别混淆:

```
Cookie 已使用: 0天2小时15分钟       ← 当前这份 Cookie 已经用了多久(绿色)
Cookie 已掉线，请重新扫码             ← Cookie 确认失效(红色)
最近验证: 2026-10-12 01:52:14       ← 保活最后一次校验通过的时刻
```

- **「已使用」不是剩余有效期**。企微没有公开 Cookie 的有效期,这个数只表示「距离上次扫码过了多久」。
- **「最近验证」每分钟都在走**,它才是判断保活是否还活着最直接的证据。如果它长时间不动,说明保活任务没跑起来。

### 扫码后要填验证码(v4.0.2 起按需弹出)

**平时详情页不显示验证码输入框**,不会常年占着二维码下方的位置。只有当企业微信真的弹出
短信验证面板时,卡片才会自动出现——并自动滚动到可见位置、把光标聚焦到输入框。
登录成功或等待超时后自动收起。

填入收到的 6 位数字提交即可,页面会显示提交结果,后台扫码任务收到后立即完成登录。
等待窗口最长 120 秒,且**收到即刻生效**,不用干等。

> 这条通道完全不依赖企业微信消息回调。旧的两条通道仍然可用:给企微应用发 `510010?`,
> 或在 AI 全局助手里发 `/wxcode 510010`。提交只改内存状态,**不会触发保存配置**,
> 所以不会把正在等待验证码的扫码任务打断。
>
> 卡片靠详情页内的轻量轮询(`GET /verify_state`,每 2.5 秒)判断是否需要出现;
> 如果打开详情页时扫码任务已经结束,卡片会保持隐藏,不打扰你。

## 常用技巧

### 微信作主通知,第三方作备用

在「第三方通知 Token」里填 `SCTxxx`,同时在「通知渠道」勾选微信。企微通知发不出去时会自动切到第三方。

### 改 IP 后不发送通知

在「第三方通知 Token」末尾加 `||Q`:

```
SCTxxx||Q
```

### 从指定 URL 获取 IP

适用于 MoviePilot 部署在需要翻墙环境。在「应用ID」栏用 `||` 接 URL:

```
应用ID,应用ID2||https://myip.net,https://ip138.net
```

### Server³ 二维码推送到服务号

在 Token 里填 `Server3的key,普通key`。失效通知走 Server³ 系统级推送,二维码推给服务号。

### 多网络出口检测

仅当你的出口 IP 会跳动(如爱快随机分流)时才需要,否则不建议开启。

```
应用ID||wan2
```

其中 `2` 表示最多保留 2 个 IP,一般设为 ≥ 宽带线路数。原理是从 orz.tools / m27.tech / skk.moe 获取多线路 IP。

> 已知问题:首次检查大概率失败,可能要第三轮才正常(可用「立即检测一次」加速)。此时无法使用「从指定URL获取IP」。

### Cookie 失效过快

在「第三方通知 Token」里至少填一个可用 Token,保存后重新进配置面板打开「IP变动后通知」。这样真正用不了企微通知时才会发通知,二维码发到第三方。

## 通知怎么发（v5.0.0 起改用宿主内置渠道）

v5.0.0 把「企业微信自建应用」那一整套能力从本插件移除了——包括应用凭据、发消息、
`/wecom` 回调验签、远程命令和控制菜单。原因是这套能力与 MoviePilot 内置的微信通知渠道重复,
而本插件的本职是**保证可信 IP 与 Cookie 一直有效**。

现在发通知只需要两步:

1. 在 MoviePilot **设定 → 通知** 里添加「微信」渠道,填企业ID / AgentId / Secret 并启用
2. 回到本插件,在「通知渠道(多选)」里勾上这个渠道,保存

这样宿主的 `post_message` 会直接走内置渠道投递,本插件只负责在 IP 变动、Cookie 失效时把消息发出去。

> 迁移提示:老版本在这里填过的企业ID / AgentId / Secret / Token / EncodingAESKey / 管理员白名单
> 已经不再使用。凭据请改填到宿主通知渠道;若这些凭据曾在明文环境里出现过,建议轮换一次。

| 命令 | 作用 |
|---|---|

## 常见问题

**Q: Cookie 老是掉怎么办?**

3.1.0 起 Cookie 会持久化到 `/config/plugins/DynamicWeChatSelfUse/settings.json`,重启和更新都不会丢。如果你仍然遇到掉线,检查两点:
1. 容器里的 `/config` 是不是真的挂载了持久卷(不是容器重建就丢的那种)
2. 日志里有没有 `没有可用的CookieCloud服务器` —— 有的话是 CookieCloud 走不通

**Q: 面板显示「保活尚未完成首轮校验」?**

说明保活循环还没成功跑过一次。等一个保活周期(默认 10 分钟),或去日志搜这几个关键字确认状态:

| 搜什么 | 说明什么 |
|---|---|
| `后台循环已启动` | 保活循环起来了没,cron 配置是什么 |
| `Cookie 保活成功` | 续期成功 |
| `cookie 校验过程中发生异常` | 浏览器起不来(最常见原因) |
| `Cookie 复核未通过` | 页面加载了但登录态没通过 |
| `获取文件锁超时` | 续期被文件锁跳过 |

**Q: 会不会触发企业微信风控?**

3.x 的保活大部分轮次只是一次轻量 HTTP 请求,只有判定失效时才启动浏览器,请求量比原版更少。如果你的账号对自动化较敏感,可以把「Cookie 保活周期」调成 `*/30 * * * *` 或 `0 */2 * * *`。企微 Cookie 有效期本身很长,10 分钟一次偏保守。

**Q: 插件市场一直拉取失败?**

日志里的 `EndOfStream` / `所有策略均无法读取插件索引` 说明 MoviePilot 的出站代理有问题(常见于代理协议填错或代理进程挂了)。这个不修的话,CookieCloud 也用不了、市场也刷不出来。

**Q: 从 4.x 升到 5.0.0 会不会丢配置?**

不会丢保活相关的任何东西:插件 ID 仍是 `DynamicWeChatSelfUse`,配置前缀仍是 `dynamicwechatselfuse_`,数据目录 `/config/plugins/DynamicWeChatSelfUse/` 原样保留,Cookie、应用ID、检测周期、通知渠道全部沿用。

变化只有一处:原来那 11 个企业微信自建应用字段(企业ID、AgentId、Secret、Token、EncodingAESKey、接收人、管理员白名单等)会从配置页消失,已保存的旧值会在下次保存时一并清除。通知改由 MoviePilot「设定 → 通知」里的内置微信渠道承担,不需要在本插件里再填一遍。

如果升级后页面还是旧版,**强制刷新(Ctrl+F5)并重载一次插件**。

**Q: 之前装过独立的 `WecomNotify` 插件怎么办?**

v4.0 起 `WecomNotify` 就不再单独发布(索引里已移除),v5.0.0 又把并入的企微通知能力一并下线。现在请把它从插件列表里卸载,通知统一在 MoviePilot「设定 → 通知」里配置。

## 3.x 相比上游改了什么

| 改动 | 说明 |
|---|---|
| **Cookie 持久化** | 扫码后写入 `settings.json`,启动时恢复。重启 / 更新插件不再丢 |
| **失效判定加退避** | 原版单轮判死——页面慢一次就清空 Cookie 并通知。现在连续 3 轮确认才判定 |
| **异常不再误杀** | 浏览器启动失败、网络抖动只记日志,绝不清 Cookie、不发「已失效」通知 |
| **复核后回写 Cookie** | 企微每次访问都会轮换会话 Cookie,原来只判有效却不保存新值 |
| **修复自我锁死** | 原版关闭 CookieCloud 时手工填的 Cookie 永远取不回来,只能重启 |
| **通知渠道可视化** | 3.1.0 起可勾选已配置的渠道,不再手打名称;支持多渠道路由 |
| **面板语义修正** | 「已使用」改为按时间戳实时计算(每分钟都在走),新增「最近验证」时间戳 |
| **保活周期可配** | 可调长以降低风控暴露 |
| **数据丢失保护** | `settings.json` 区分「文件不存在」与「无法解析」,拒绝覆盖损坏文件;原子写 + 并发锁 |

## 版本历史

完整历史见 `package.v3.json`。

- **5.0.0** 当前版本:精简为「只管可信 IP 与 Cookie 保活」。移除企业微信自建应用那一整套配置(通知渠道名称、消息类型、企业ID、AgentId、Secret、代理地址、回调 Token、EncodingAESKey、接收人、管理员白名单、自动注册控制菜单),连带移除自建应用发消息、`/wecom` 回调验签、远程命令与菜单注册,以及 `/wecom_test`、`/wecom_status` 两条命令。**通知请直接使用 MoviePilot 内置的微信通知渠道。**
- **4.0.2** 验证码卡片改为按需弹出——平时不显示,只有企业微信要求短信验证时才自动出现并聚焦,登录后自动收起
- **4.0.1** 详情页新增短信验证码输入框与提交按钮,无需回调即可完成「扫码 → 填码」;验证码等待改为轮询
- **4.0.0** 并入企业微信通知(原独立插件 `WecomNotify`),完整保留 IP 保活;插件 ID 与配置前缀不变,升级不丢原有配置与 Cookie
- **3.2.0** 插件 ID 改为 `DynamicWeChatSelfUse`,与官方同名插件共存
- **3.1.3** 面板计时实时化 + 掉线提示
- **3.1.2** 面板语义修正 + 最近验证时间戳
- **3.1.1** 修复「已使用」重启后恒为 0
- **3.1.0** 通知渠道多选 + userid 字段
- **3.0.0** V3 专用实现,迁移到 `app.sdk.*` 稳定 SDK
