# 动态企微可信IP（自用版）

一个插件同时做两件事：

1. **动态可信 IP 保活**：定时检查本机公网 IP,变化时自动写回企业微信应用的「可信 IP」列表,并把登录 Cookie 持久化到磁盘,**保证企业微信通知不会因为 IP 变动或重启而失效**。
2. **企业微信通知（v4.0 起内置）**：把 MoviePilot 通知推送到企业微信自建应用,支持回调验签与解密、远程命令、控制菜单和管理员白名单。

> **v4.0 起,原独立插件 `WecomNotify`（PR #1）的能力已并入本插件,不再单独发布。** 插件 ID 仍是
> `DynamicWeChatSelfUse`,配置前缀仍是 `dynamicwechatselfuse_`,**升级不会丢原有应用ID、Cookie 与通知渠道配置**。
> 只想要 IP 保活的老用户可以直接跳过所有企业微信通知相关字段,旧功能完全不受影响。

> **本插件名为「动态企微可信IP（自用版）」，用于和插件市场上的同名官方插件区分，请勿混淆。**
> 本仓库是 [RamenRa/MoviePilot-Plugins](https://github.com/RamenRa/MoviePilot-Plugins) 中同名插件的独立维护分支,原始作者 RamenRa,原始创意来自 [suraxiuxiu/MoviePilot-Plugins](https://github.com/suraxiuxiu/MoviePilot-Plugins/)。
>
> 开发者交接文档（状态快照、权威数据源、机制说明、验收判据、红线清单、踩坑档案）见仓库根目录 [HANDOVER.md](HANDOVER.md)。

## 这个插件解决什么问题

企业微信应用只能从「可信 IP」列表里的地址发消息。家里宽带的公网 IP 一变,企微应用就发不出通知了——表现为「明明网络没问题,但微信收不到任何消息」。

本插件做的就是:每隔一段时间查一次公网 IP,变了就自动登录企微后台把新 IP 填进可信 IP 列表,你什么都不用管。

顺带解决第二个痛点:**Cookie 反复失效**。企微后台的登录 Cookie 是有时效的,原版插件只把它存在内存里,重启或更新插件就没了,必须重新扫码。本仓库的 3.x 版本把 Cookie 持久化到磁盘,重启和更新都不会丢。

## 安装

### 方式一:插件市场(推荐)

1. 进入 **系统 → 插件 → 插件市场**
2. 添加仓库地址:
   ```
   https://github.com/laoying6663/MoviePilot-Plugins
   ```
3. 刷新市场,搜索「动态企微可信IP」并安装
4. 安装后在插件列表里**重载一次插件**

> 市场拉取失败(日志报 `EndOfStream` / `所有策略均无法读取插件索引`)说明你的 MoviePilot 出站代理有问题,先解决代理再回来刷新,否则装不上新版。

### 方式二:手动放进容器

市场刷新不了时用这个,绕过索引直接覆盖代码:

```bash
# 把仓库里的 plugins.v3/dynamicwechatselfuse 目录拷进容器
docker cp ./dynamicwechatselfuse <容器名>:/app/app/plugins/DynamicWeChatSelfUse
```

然后在 MoviePilot 里**重载插件**或重启容器。

> 数据目录 `/config/plugins/DynamicWeChatSelfUse/` 与代码目录是分开的,更新插件不会动你的 Cookie 和配置。

## 快速开始

1. **填应用 ID** —— 打开企业微信管理后台的应用详情页,地址栏末尾那串数字就是应用 ID。多个应用用英文逗号分隔。
2. **配通知渠道** —— 在插件配置里勾选你已在 MoviePilot「设定 → 通知」中配置好的渠道(3.1.0 起支持多选,不用再手打 `WeChat` 这种名字)。至少配一个才能用 `/push_qr`。
3. **保存配置** —— 这一步不能跳过,配置要落库才会生效。
4. **扫码登录一次** —— 用面板里的「本地扫码修改IP」,或在企微应用里发 `/push_qr`。扫完 Cookie 就存下来了,之后重启、更新都不会再丢。
   - 扫码后若企业微信要求短信验证码,**详情页会自动弹出「短信验证码」输入框**(v4.0.2 起,平时不显示、需要时才出现),填 6 位数字点「提交验证码」即可。不需要配置企业微信消息回调,也不需要 AI 全局助手。
   - 备用通道仍保留:给企业微信应用发 `6位数字?`(如 `510010?`),或启用 AI 全局助手后发 `/wxcode 510010`。
5. **(可选)开启企业微信通知** —— 见下方「企业微信通知（v4.0 起内置）」。只想要 IP 保活的话这一步可以跳过。

## 面板说明

插件面板上有两个数字,含义不同,别混淆:

```
Cookie 已使用: 0天2小时15分钟       ← 当前这份 Cookie 已经用了多久(绿色)
Cookie 已掉线，请重新扫码             ← Cookie 确认失效(红色)
最近验证: 2026-10-12 01:52:14       ← 保活最后一次校验通过的时刻
```

- **「已使用」不是剩余有效期**。企微没有公开 Cookie 的有效期,这个数只表示「距离上次扫码过了多久」。
- **「最近验证」每分钟都在走**,它才是判断保活是否还活着最直接的证据。如果它长时间不动,说明保活任务没跑起来。

### 扫码后要填验证码(v4.0.2 起按需弹出)

**平时详情页不显示验证码输入框**,不会常年占着二维码下方的位置。只有当企业微信真的弹出
短信验证面板时,卡片才会自动出现——并自动滚动到可见位置、把光标聚焦到输入框。
登录成功或等待超时后自动收起。

填入收到的 6 位数字提交即可,页面会显示提交结果,后台扫码任务收到后立即完成登录。
等待窗口最长 120 秒,且**收到即刻生效**,不用干等。

> 这条通道完全不依赖企业微信消息回调。旧的两条通道仍然可用:给企微应用发 `510010?`,
> 或在 AI 全局助手里发 `/wxcode 510010`。提交只改内存状态,**不会触发保存配置**,
> 所以不会把正在等待验证码的扫码任务打断。
>
> 卡片靠详情页内的轻量轮询(`GET /verify_state`,每 2.5 秒)判断是否需要出现;
> 如果打开详情页时扫码任务已经结束,卡片会保持隐藏,不打扰你。

## 常用技巧

### 微信作主通知,第三方作备用

在「第三方通知 Token」里填 `SCTxxx`,同时在「通知渠道」勾选微信。企微通知发不出去时会自动切到第三方。

### 改 IP 后不发送通知

在「第三方通知 Token」末尾加 `||Q`:

```
SCTxxx||Q
```

### 从指定 URL 获取 IP

适用于 MoviePilot 部署在需要翻墙环境。在「应用ID」栏用 `||` 接 URL:

```
应用ID,应用ID2||https://myip.net,https://ip138.net
```

### Server³ 二维码推送到服务号

在 Token 里填 `Server3的key,普通key`。失效通知走 Server³ 系统级推送,二维码推给服务号。

### 多网络出口检测

仅当你的出口 IP 会跳动(如爱快随机分流)时才需要,否则不建议开启。

```
应用ID||wan2
```

其中 `2` 表示最多保留 2 个 IP,一般设为 ≥ 宽带线路数。原理是从 orz.tools / m27.tech / skk.moe 获取多线路 IP。

> 已知问题:首次检查大概率失败,可能要第三轮才正常(可用「立即检测一次」加速)。此时无法使用「从指定URL获取IP」。

### Cookie 失效过快

在「第三方通知 Token」里至少填一个可用 Token,保存后重新进配置面板打开「IP变动后通知」。这样真正用不了企微通知时才会发通知,二维码发到第三方。

## 企业微信通知（v4.0 起内置）

原独立插件 `WecomNotify` 的能力已并入本插件:监听宿主的 `NoticeMessage` 事件把通知推送到
企业微信自建应用,同时接收企业微信推来的消息,验签解密后执行远程命令。**不注册新的通知渠道**
(宿主 `NotificationChannel` 是封闭枚举),回复消息由插件自己调企业微信 API 发送,不会经过
宿主 `post_message`,因此不会造成通知回环。

### 能做什么

- **通知推送**:按消息类型筛选;带封面图的通知走图文(news)消息;正文超过 2048 字节自动分块,不切断中文等多字节字符
- **消息回调**:SHA1 签名校验 + AES-256-CBC 解密,5 秒内返回 `success`
- **远程命令**:`/wecom_status`、`/wecom_test`、`/help`,详见下方命令表
- **控制菜单**:按已注册命令自动创建企业微信应用菜单(一级最多 3 个、二级最多 5 个)
- **管理员白名单**:限制谁可以执行斜杠命令
- **转发代理**:适配「2022-06-20 之后创建的自建应用需固定可信 IP」的限制,和本插件的 IP 保活正好互补

### 配置字段

| 字段 | 说明 |
|---|---|
| **企业ID (corpid)** | 企业微信后台 `我的企业 → 企业信息` 底部 |
| **应用 AgentId** | 企业微信后台 `应用管理 → 自建应用` 详情页 |
| **应用 Secret** | 同上 |
| **代理地址** | 消息转发代理,留空直连 `https://qyapi.weixin.qq.com` |
| **Token** | 应用 `接收消息` 页面生成,用于回调验签 |
| **EncodingAESKey** | 同上,43 位,用于回调解密 |
| **接收人 userid** | 指定成员,留空发给应用可见的全部成员 |
| **管理员白名单** | 可执行命令的用户 ID,多个用英文逗号分隔。**白名单为空时任何人都能执行命令,生产环境务必配置** |
| **消息类型筛选** | 只转发勾选的 MoviePilot 通知类型,留空表示全部 |
| **自动创建控制菜单** | 开启后按已注册命令建菜单 |
| **通知渠道名称** | 仅作为非命令消息广播的来源标识,默认「企业微信」 |

> **代理地址是转发代理,不是反向代理**。它需要把 `/cgi-bin/gettoken`、
> `/cgi-bin/message/send`、`/cgi-bin/menu/create` 转发到 `qyapi.weixin.qq.com`,
> 并把代理机的真实 IP 加入企业微信应用的 IP 白名单。

### 启用消息回调

1. 填好企业ID / 应用 AgentId / 应用 Secret / Token / EncodingAESKey,保存配置
2. 在企业微信应用 `接收消息` 页面填入回调 URL(**注意插件 ID 是 `DynamicWeChatSelfUse`**):

```text
http(s)://<你的域名>:<端口>/api/v1/plugin/DynamicWeChatSelfUse/wecom
```

3. 需要公网可访问并做好端口转发。保存成功即表示验签通过(插件返回解密后的 `echostr`)
4. 打开「自动创建控制菜单」开关,插件会按已注册命令创建应用菜单

> 回调接口是匿名的(`auth: none`),安全性完全由企业微信 SHA1 签名承担——攻击者算不出签名。
> **不要**把它改成需要登录,那样企业微信回调会直接失败。

### 与宿主内置「企业微信」渠道的区别

| 能力 | 内置渠道 | 本插件 |
| --- | --- | --- |
| 通知推送 | ✅ | ✅ |
| 消息回调 / 远程命令 | ✅ | ✅(仅本插件注册的命令) |
| 自动菜单 | ✅ | ✅ |
| 在 `设定 → 通知` 里作为系统渠道出现 | ✅ | ❌ |
| 使用宿主内置斜杠命令(如 `/site_signin`) | ✅ | ❌ |

后两条是宿主合同的硬限制,不是实现取舍。非命令消息会以 `EventType.UserMessage` 广播,
其它插件仍可监听(本插件自己的验证码监听也走这条链路)。

### 依赖与调试

- 回调加解密需要 `pycryptodome`,MoviePilot 主程序已内置。环境缺失时插件仍能加载,推送不受影响,仅回调不可用,面板与日志会提示
- 插件详情页下半部分展示当前企微通知配置、最近一次发送结果、加解密依赖状态和回调地址
- `GET /api/v1/plugin/DynamicWeChatSelfUse/status` 返回运行状态(需登录)
- 日志中所有企微通知相关输出都带 `[企业微信通知]` 前缀
- 企业微信后台轮换过凭据后,记得在插件配置页同步更新并**强制刷新(Ctrl+F5)+ 重载插件**

## 远程命令

在企业微信应用里直接发给 MoviePilot:

| 命令 | 作用 |
|---|---|
| `/push_qr` | 推送登录二维码。也可用来**测试通知通道是否可用** |
| `/wxcode 550110` | 发送短信验证码(需要启用 AI 全局助手;v4.0.1 起也可直接在插件详情页输入) |
| `/wecom_status` | v4.0 查看企业微信通知配置与连通性 |
| `/wecom_test` | v4.0 发送一条企业微信测试消息 |
| `/help` 或 `/帮助` | v4.0 列出全部可用命令 |

前两条沿用 3.x 的动态可信 IP / 扫码链路;后三条来自 v4.0 并入的企业微信通知能力,
既可以在企业微信应用里直接发,也可以点控制菜单触发,受管理员白名单约束。
「立即运行一次」在企微凭据配置完整时也会顺带发一条测试消息。

> MoviePilot 可能因网络波动收不到命令,尤其是用 Cloudflare 隧道的用户。多发几次,以 **MP 日志为准**。

## 常见问题

**Q: Cookie 老是掉怎么办?**

3.1.0 起 Cookie 会持久化到 `/config/plugins/DynamicWeChatSelfUse/settings.json`,重启和更新都不会丢。如果你仍然遇到掉线,检查两点:
1. 容器里的 `/config` 是不是真的挂载了持久卷(不是容器重建就丢的那种)
2. 日志里有没有 `没有可用的CookieCloud服务器` —— 有的话是 CookieCloud 走不通

**Q: 面板显示「保活尚未完成首轮校验」?**

说明保活循环还没成功跑过一次。等一个保活周期(默认 10 分钟),或去日志搜这几个关键字确认状态:

| 搜什么 | 说明什么 |
|---|---|
| `后台循环已启动` | 保活循环起来了没,cron 配置是什么 |
| `Cookie 保活成功` | 续期成功 |
| `cookie 校验过程中发生异常` | 浏览器起不来(最常见原因) |
| `Cookie 复核未通过` | 页面加载了但登录态没通过 |
| `获取文件锁超时` | 续期被文件锁跳过 |

**Q: 会不会触发企业微信风控?**

3.x 的保活大部分轮次只是一次轻量 HTTP 请求,只有判定失效时才启动浏览器,请求量比原版更少。如果你的账号对自动化较敏感,可以把「Cookie 保活周期」调成 `*/30 * * * *` 或 `0 */2 * * *`。企微 Cookie 有效期本身很长,10 分钟一次偏保守。

**Q: 插件市场一直拉取失败?**

日志里的 `EndOfStream` / `所有策略均无法读取插件索引` 说明 MoviePilot 的出站代理有问题(常见于代理协议填错或代理进程挂了)。这个不修的话,CookieCloud 也用不了、市场也刷不出来。

**Q: 从 3.2.0 升到 4.0.0 会不会要重新扫码 / 重新填配置?**

不会。插件 ID 仍是 `DynamicWeChatSelfUse`,配置前缀仍是 `dynamicwechatselfuse_`,数据目录
`/config/plugins/DynamicWeChatSelfUse/` 原样保留。升级只是多出一组企业微信通知字段,
不填就完全沿用旧行为。如果升级后页面还是旧版,**强制刷新(Ctrl+F5)并重载一次插件**。

**Q: 之前装过独立的 `WecomNotify` 插件怎么办?**

v4.0 起 `WecomNotify` 不再单独发布(索引里已移除)。把原先填在那边的
企业ID / AgentId / Secret / Token / EncodingAESKey 抄到本插件配置页即可;
回调 URL 要改成 `/api/v1/plugin/DynamicWeChatSelfUse/wecom`。

## 3.x 相比上游改了什么

| 改动 | 说明 |
|---|---|
| **Cookie 持久化** | 扫码后写入 `settings.json`,启动时恢复。重启 / 更新插件不再丢 |
| **失效判定加退避** | 原版单轮判死——页面慢一次就清空 Cookie 并通知。现在连续 3 轮确认才判定 |
| **异常不再误杀** | 浏览器启动失败、网络抖动只记日志,绝不清 Cookie、不发「已失效」通知 |
| **复核后回写 Cookie** | 企微每次访问都会轮换会话 Cookie,原来只判有效却不保存新值 |
| **修复自我锁死** | 原版关闭 CookieCloud 时手工填的 Cookie 永远取不回来,只能重启 |
| **通知渠道可视化** | 3.1.0 起可勾选已配置的渠道,不再手打名称;支持多渠道路由 |
